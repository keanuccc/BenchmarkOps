# 复杂评测套件 v2 — 数据 / 基准 / 提示词 说明

> 本套数据为 **BenchmarkOps** 的「复杂实验」演示数据，目标是在**真实可跑的模型**上做多任务、大数据量的评测。
> 所有实体已通过后端 API 创建，可在前端「项目 → 复杂评测套件 v2」中查看。

## 0. 概览

| 维度 | 内容 |
|------|------|
| 项目 | **复杂评测套件 v2**（project_id 见后端，前端可直接选） |
| 数据集 | 4 个，共 **1500 行** |
| 基准 | 4 个，覆盖 qa / coding / classification / generation 四类指标 |
| 提示词 | 4 个，含思维链(CoT) / 少样本(few-shot) / 角色设定 / 代码约束 |
| 数据生成 | 确定性生成（`generate_datasets.py`），可复现、无随机源 |

> ⚠️ 当前后端 `provider_mode = openrouter`（真实模型）。**免费模型每日额度有限**，
> 跑全部 1500 行会消耗真实额度/费用且较慢。**建议先用小批量试跑**（见 §5）。

## 1. 数据集（4 个，共 1500 行）

| 文件 / 名称 | 行数 | 任务类型 | 字段 | expected 字段 | 样例 |
|------|------|------|------|------|------|
| `multihop_qa.jsonl` **多跳推理QA** | 300 | qa | `question` | `answer` | 国家→首都→大洲 链；元素→序数→性质；数学运算链；逻辑/历史/单位换算链 |
| `codegen.jsonl` **代码生成任务** | 500 | coding | `prompt` | `answer`（关键函数签名） | 20 类算法任务 × 8 种语言 × 多种约束 → 期望含 `def fibonacci` 等 |
| `classification.jsonl` **文本分类** | 400 | classification | `text` | `answer`（类别） | 体育/科技/财经/娱乐/政治/健康 六类新闻 |
| `summarization.jsonl` **摘要生成** | 300 | generation | `article` | `answer`（参考摘要） | 5 篇新闻 × 5 种导语背景，期望一句话关键摘要 |

- 每行一个 JSON 对象；含 `answer` 的行会被解析器自动识别为 `expected`（评测对比目标）。
- `input` = 除 `answer` 外的其余字段，用于渲染提示词模板变量（如 `{question}`）。

## 2. 基准（4 个）

| 名称 | type | metric | 含义 |
|------|------|--------|------|
| 多跳推理QA基准 | `qa` | `exact_match_ci` | 对简短答案做**大小写不敏感**精确匹配 |
| 代码生成基准 | `coding` | `contains` | 判定模型输出**是否包含**期望的函数签名/片段 |
| 文本分类基准 | `classification` | `exact_match_ci` | 对六类分类结果做精确匹配 |
| 摘要生成基准 | `generation` | `f1_token` | 以 **token 级 F1** 评估生成摘要与参考摘要的重叠 |

> metric 取值来自后端白名单：`contains / exact_match / exact_match_ci / f1_token / numeric_match`。

## 3. 提示词（4 个，自动识别变量）

| 名称 | 变量 | 设计要点 |
|------|------|------|
| **思维链推理提示** | `question` | 强制模型先逐步推理（Chain-of-Thought），仅最后一行以「答案：」给出结论 |
| **少样本分类提示** | `text` | 内嵌 3 个示例（few-shot），约束输出为单一类别名，禁止解释 |
| **角色设定+结构化输出提示** | `prompt` | 资深工程师人设 + 强制 JSON 结构 `{thought, code, tests}` 输出 |
| **摘要生成提示** | `article` | 新闻编辑人设 + 紧凑输出约束（≤40 字，覆盖主体/动作/关键数字） |

> 变量由系统从模板 `{...}` 自动抽取，与数据集字段名对应（question/text/prompt/article）。

## 4. 组合出来的「复杂实验」候选

同一项目下可组合出多组实验，例如：

| 实验 | 数据集 | 基准 | 提示词 | 模型（真实） |
|------|------|------|------|------|
| 多跳推理 | 多跳推理QA | 多跳推理QA基准 | 思维链推理提示 | GPT-4o mini / Claude 3.5 Haiku |
| 代码生成 | 代码生成任务 | 代码生成基准 | 角色设定+结构化输出提示 | GPT-4o / Claude 3.5 Sonnet |
| 文本分类 | 文本分类 | 文本分类基准 | 少样本分类提示 | GPT-4o mini |
| 摘要生成 | 摘要生成 | 摘要生成基准 | 摘要生成提示 | GPT-4o mini |

可在前端「实验」页用「基于已有实验」下拉**只换模型**快速做多模型对比（见历史改动）。

## 5. 如何运行（建议先用小批量）

真实模型下，建议先取每个数据集的**前 N 行**试跑，确认链路与成本后再全量：

```bash
# 取前 20 行做小批量数据集（示例：多跳推理）
head -n 20 sample-data/complex/multihop_qa.jsonl > /tmp/small_qa.jsonl
# 然后通过前端「数据集 → 上传」选择该项目上传 /models? 不，用 datasets 上传接口
```

或直接在**前端**操作：
1. 打开项目「复杂评测套件 v2」。
2. 数据集 / 基准 / 提示词 已就绪，直接去「实验」页新建实验并选组合。
3. 创建后点「运行」，后端调用真实 OpenRouter 模型逐行推理并打分。
4. 跑完多组后到「对比 / 报告」查看横向对比与中文 AI 报告。
