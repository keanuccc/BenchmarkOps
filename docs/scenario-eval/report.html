  • 失败行为：仅输出函数中的 return 行，而不是完整函数定义。

  • 5 条失败样本均只输出前缀，没有摘要内容。

综上，失败並非随机错误，而是模型在生成答案时“只输出格式前缀/输入复述/代码片段，未继续生成核心内容”的系统性问题。failure_rate 为 0 表示没有发生服务或评分异常，但语义和格式层面的失败大量存在。

建议

  1. 修正 Prompt 指令 - 明确要求「不要输出前缀，直接输出最终答案」。 - 在 QA、GEN 中禁止输出 答案：、摘要： 等占位前缀。 - 在 CLASS 中要求直接输出分类标签，例如 体育 而不是 类别：体育。

  2. 针对 AGENT 使用结构化工具调用 - 当前 AGENT 输出为原始问题文本，无法完成工具调用。 - 应接入 function calling / tool call 格式，要求输出 function_name 和 arguments，并进行 JSON 校验。

  3. 针对 CODING 增加完整代码约束 - 要求输出完整函数体，不能只输出 return 语句。 - 可要求用 Markdown 代码块包裹，并在评估前提取完整函数。

  4. 增加输出完整性检测 - 对仅输出前缀、仅复述输入的样本，直接判定为失败并触发一次重试。 - 重试 prompt 可追加「你的回答不完整，请补全」等提示。

  5. 扩展样本量 - 每个场景仅 10 条数据，统计波动较大；建议扩充到至少 50 条/场景，以便获得更稳定的准确率估计。
