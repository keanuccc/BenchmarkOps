# 真实模型跨网关评测：结果与分析

> 本评测是 BenchmarkOps 平台在**真实模型、真实数据集、真实网关**上的一次完整
> 端到端验证：C-Eval（61 条中文考试真题）+ THUCNews（120 条新闻分类），
> 3 个模型，路由到七牛云 AI 与 OpenRouter 两个网关，共 6 个实验、482 次真实
> 模型调用。完整数据见 [results.json](results.json)，平台自动生成的报告见
> [report.md](report.md)，一键复现见
> [sample-data/real-world/README.md](../../sample-data/real-world/README.md)。

## 1. 结果总览

| 模型 | 网关 | C-Eval 问答 | THUCNews 分类 | 平均延迟/行 | 总 Token | 总成本 |
|---|---|---:|---:|---:|---:|---:|
| **Doubao Seed 2.0 Pro** | 七牛云 AI | **91.80%** | **93.33%** | 5.3–12.6s | 155K | $0* |
| **DeepSeek V3** | 七牛云 AI | 70.49% | 84.17% | **1.2s** | 90K | $0* |
| **GPT-4o mini** | OpenRouter | 55.74% | 84.17% | 1.6–1.9s | 105K | **$15.83** |

\* 七牛云网关未回传计费字段，成本按 $0 记录（详见第 4 节成本讨论）。

## 2. 关键发现

### 2.1 准确率：Doubao 断层领先

- Doubao Seed 2.0 Pro 在两个任务上都拿到第一：C-Eval 91.80%（领先第二名
  **21.3 个百分点**），THUCNews 93.33%。
- DeepSeek V3 在 THUCNews 上与 GPT-4o mini 打平（84.17%），但在 C-Eval 上
  高出 **14.75 个百分点**——中文专业考试场景下差距明显。
- GPT-4o mini 在 C-Eval 上不足 60%，与它在中文考试场景的短板一致。

### 2.2 延迟：DeepSeek V3 性价比之王

- DeepSeek V3 平均每行 **1.2 秒**（C-Eval 和 THUCNews 一致），吞吐最高。
- GPT-4o mini 每行 1.6–1.9 秒，居中。
- Doubao 每行 **5.3–12.6 秒**（C-Eval 上更慢），适合离线批量，不适合在线。

### 2.3 成本：OpenRouter 计费透明，七牛网关未回传

- GPT-4o mini 两个实验共花费 **$15.83**（THUCNews 120 行 $14.65，C-Eval 61 行
  $1.18），每千 Token 成本约 $0.15，与官方定价一致——说明平台成本核算链路正确。
- 七牛网关未在响应中回传 usage 计费字段，平台按 $0 记录。这是一个已知的
  **数据缺口**（非错误）：生产使用时应配置七牛侧计费回传，否则成本分析不完整。

### 2.4 失败模式：空输出是最大质量风险

平台报告逐行分析了评分不匹配样本，结论有很强的可操作性：

- **类别混淆**集中在「时政↔财经」「房产↔财经/时政」「时尚↔娱乐」，多个模型
  犯同样的错，说明类别边界本身有歧义；
- **空输出**：GPT-4o mini 3 次、Doubao 1 次，模型没有遵守"只输出标签"的指令；
- **专业题全军覆没**：C-Eval 的 TCP 确认号计算题三个模型全错（正确答案 B）。

## 3. 平台能力验证（这次评测证明了什么）

1. **多网关可插拔**：同一套评测流程同时路由七牛云与 OpenRouter，Provider
   注册表按模型元数据自动选择网关，业务层零改动；
2. **真实计费核算**：OpenRouter 的成本、Token、延迟被逐行采集并汇总进报告，
   与官方定价吻合；
3. **失败不中断**：评测过程中出现过模型 502（kimi-k2 / glm-4.5）、免费额度
   耗尽（Tencent HY3 free）、服务重启（开发环境热重载）等真实故障，平台分别
   以 failed / partial / 恢复标记处理，没有把失败数据混入成功结果；
4. **报告自动化**：本报告（含失败模式分析）由平台内置的 AI 报告管线基于
   实验结果自动生成（`generated_by: qiniu`），无需人工整理。

## 4. 已知限制与后续

- **样本量**：61/120 条，统计置信度有限；后续扩到 500+ 条并给出置信区间；
- **成本缺口**：七牛网关计费字段未回传，TCO 对比不完整；
- **HumanEval**：平台 `contains` 指标对真实代码生成过严，需接入测试用例判定
  指标（`code_pass`）才能给出有意义的通过率；
- **评测口径**：全部为 temperature=0 的确定性输出，未覆盖多次采样（pass@k）。

## 5. 复现

```bash
cd backend
python scripts/run_real_eval.py            # 默认 3 模型 x 2 数据集
python scripts/run_real_eval.py --limit 3  # 冒烟测试
```

前置条件：`backend/.env` 配置 `OPENROUTER_API_KEY` / `QINIU_API_KEY`（至少一个，
对应网关的模型会自动启用）。结果写入 `docs/real-world-eval/`。
